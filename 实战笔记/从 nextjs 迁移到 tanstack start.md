## 为什么要迁移

### 开发体验差异

这点是我确实能感受到的差距，开发体验，next 开发太慢了（相对于基于 vite 来讲）本来开发时间就分散，等待启动时间很长。

当更新内容后，也不能及时的响应，需要额外的时间去等待

debug 困难，为了避免问题，去写一些不符合正常逻辑的代码

### 部署差异

nextjs 运行环境绑定 Vercel，在 vercel 上部署，直接享受很多便利，包含了所有基础设施（CDN、边缘计算、图片优化、构建缓存）。

单价高，但部署流程简单，自动构建 → 自动部署 → 自动分配域名 → 自动 HTTPS。

在非 Vercel 环境下，你失去了 Next.js 最引以为傲的“零配置优化”，反而需要大量时间实现功能，自管理镜像，配置 CI/CD，代理，SSL 证书，监控日志和错误追踪。为复杂的抽象层付费（学习成本、运维成本），却没有享受到它带来的基础设施红利。

我在自己的 docker 上进行部署。

### 能带来哪些东西

更快的构建速度，更完善的类型安全，更快的首屏加载，更完整的应用控制（避免 next 默认行为的黑盒）

不用去学习 RSC 范式，更灵活的开发
